Background

Problem Background & Statements

Four core operational bottlenecks in campus equipment logistics at UPTM

01

Inefficient Manual Paperwork

Time Delay
  • Organizers must physically travel to HEP or facilities offices to submit forms.
  • Signature verification takes 2-3 working days, disrupting urgent event deadlines.
  • Physical forms get misplaced or discarded without permanent digital backups.
02

Double-Booking & Schedule Collisions

Schedule Conflict
  • No synchronized master calendar exists between clubs and departments.
  • High-demand equipment (PA sound systems, microphones, projectors) booked simultaneously.
  • Collisions only discovered during event setup, resulting in severe disruption.
03

Inaccurate Inventory & Stock Mismatches

Lack of Visibility
  • Stock counts recorded in static books become instantly obsolete upon loans.
  • Damaged or retired assets are not subtracted in real time, displaying false availability.
  • Students plan events assuming items exist, only to face rejection at the store.
04

Lack of Damage Tracking & Accountability

Untracked Loss
  • Post-event returns lack formal inspection; damaged gear returned unnoticed.
  • No standardized grading scale for defect severity or repair cost recovery.
  • University bears recurring replacement costs due to unassigned responsibility.

Database

Database Architecture: 3NF Relational ERD

Optimized 8-table schema normalized to Third Normal Form (3NF) ensuring zero redundancy

RELATIONAL ENTITIES (3NF)
  • users: Authentication, matric ID, hashed password & role.
  • categories: Audio, Visual, Electrical & Stage categories.
  • equipment: Specifications, stock counts & maintenance status.
  • packages: Curated bundled packages with event descriptions.
  • package_items: Junction table mapping equipment to packages.
  • bookings: Master reservation dates, status & user ID.
  • booking_items: Line items linking equipment and loan quantity.
  • damage_reports: Post-return defect logs, severity & fines.
3NF Guarantee: Strict atomic attributes (1NF), composite keys in junction tables (2NF), and zero transitive dependencies (3NF) with InnoDB cascade integrity.

Innovation

Innovation 1: Automated Conflict Detection Engine

Algorithmic elimination of equipment double bookings via real-time date-overlap evaluation

The Traditional Flaw: Static Shelf Checking

Manual systems check what is sitting on the warehouse shelf today, ignoring future reservation commitments. When two clubs request gear for the same weekend, double bookings occur.

PinjamGeng Mathematical Algorithm

For requested dates [Start_Req, End_Req]:
1. System queries active loans overlapping the date range.
2. Available_Stock = Total_Stock - SUM(Allocated_Qty).
3. If Requested > Available -> Instant block & prompt.

Verified Impact:

• 100% elimination of double-booking collisions.
• Dynamic stock adjustment in microseconds.
• Provides real-time alternative date suggestions.

BACKEND SQL LOGIC IMPLEMENTATION
SELECT e.id, e.name, e.total_quantity, COALESCE(SUM(bi.quantity), 0) AS booked_quantity, (e.total_quantity - COALESCE(SUM(bi.quantity), 0)) AS available_stock FROM equipment e LEFT JOIN booking_items bi ON e.id = bi.equipment_id LEFT JOIN bookings b ON bi.booking_id = b.id AND b.status IN ('Approved', 'In Use') AND (b.start_date <= :request_end_date AND b.end_date >= :request_start_date) WHERE e.id = :equipment_id GROUP BY e.id;
Live Execution Example:
Campus stock = 4 PA Sets. Active booking for 15-16 Oct = 3 PA Sets.
Club B requests 2 PA Sets for 16 Oct -> System calculates 4 - 3 = 1 Available.
Booking blocked immediately with warning: "Only 1 unit available for selected date range."

Innovation

Innovation 3: Return & Damage Tracking Engine

Standardized 4-tier defect grading, automated fine computation, and digital audit trail

STANDARDIZED 4-TIER DEFECT SEVERITY
Tier 1: Minor Damage 10% FINE

Cosmetic scratches, loose knobs, minor casing scuffs. Item functional.

Tier 2: Moderate Damage 30% FINE

Cracked housing, frayed cables, faulty connector pins requiring repair.

Tier 3: Severe Damage 60% FINE

Blown speaker driver, damaged projector lens, shattered screen.

Tier 4: Total Loss / Missing 100% REPLACEMENT

Equipment missing or damaged beyond economical repair.

ACCOUNTABILITY LIFECYCLE
  • 1. Check-In Physical Inspection: Officer inspects equipment upon return.
  • 2. Incident Logging in Database: Officer logs defect notes and tags user ID.
  • 3. Automated Fine Computation: Algorithm calculates penalty based on item valuation.
  • 4. Automatic Status Lock: Item condition set to "Under Maintenance" to block re-loans.
  • 5. Digital Return Receipt Issued: Timestamped receipt generated for student.
Institutional Value: Transfers financial liability to responsible borrowers, incentivizing respectful asset handling and saving university funds.

Technology Stack & Security Architecture

Multi-tier technical framework adhering to OWASP web security standards

MULTI-TIER ARCHITECTURE
Presentation Tier (Frontend):

HTML5, CSS3, JavaScript ES6+, Bootstrap 5, FontAwesome, SweetAlert2.

Application Tier (Backend):

PHP 8.2 with modular Model-View-Controller (MVC) architecture and helper services.

Data Tier (Database):

MySQL / MariaDB 10.4 with InnoDB storage engine and 3NF foreign key constraints.

Cloud Hosting:

Apache Web Server, remote MySQL cluster, InfinityFree cloud hosting.

SECURITY & DEFENSIVE MEASURES
🔒 Bcrypt Password Hashing:

Passwords salted and hashed using PHP PASSWORD_DEFAULT (Bcrypt).

🔒 SQL Injection Prevention:

100% of queries use PDO Prepared Statements with bound parameters.

🔒 XSS Sanitization:

All user inputs sanitized through htmlspecialchars() before DOM rendering.

🔒 Role-Based Session Guard (RBAC):

Administrative routes strictly protected by server-side session checks.
